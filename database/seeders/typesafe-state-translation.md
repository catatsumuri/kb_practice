# 状態 {#state}

> 状態とは何か、どのように構造化するか、そしてSystem Oneモデルに必要なコンテキストをどのように与えるか。

**状態**とは、System Oneモデルに評価を依頼するコンテンツです。サポートメッセージ、テキストの一節、またはアプリケーションの現在の状態などが該当します。状態は、回答を求める質問とともに、APIリクエストの`state`フィールドに渡します。

各リクエストは、1つの状態を1つ以上の質問に対して評価します。すべての質問は同じ状態を参照し、それぞれ独立して評価されます。1つのリクエストに[Choice](/primitives/choice)、[Score](/primitives/score)、[Noul](/primitives/noul)の質問を混在させることができます。

## 状態はシンプルな文字列または構造化されたJSON値にできます {#state-can-be-a-simple-string-or-a-structured-json-value}

最もシンプルな状態はプレーンな文字列です：

```python theme={null}
state = "カードが2回請求されました。"
```

状態はJSONオブジェクトや配列にすることもでき、モデルが関連する質問に回答するのに役立つ関連コンテキスト、例、その他の情報を含めることができます。状態とは、専門家のパネルに判断を求める前に提示する資料だと考えてください。Pythonでは、対応する文字列、辞書、またはリストを`client.system_one(state=...)`に直接渡します。

| フォーマット | 用途 | 例 |
| - | - | - |
| 文字列 | メッセージ、記事、または一節 | `"カードが2回請求されました。"` |
| オブジェクト | 名前付きフィールド、関連レコード、またはアプリケーションの状態 | `{"message": "カードが2回請求されました。", "order_id": "A-104"}` |
| 配列 | メッセージやレコードのシーケンス | `["こんにちは", "顧客番号はTS1337です。", "カードが2回請求されました。"]` |

各リクエストにはオブジェクトを使用することで、状態の各部分に説明的な名前を付け、その関係を明確に保つことができます。ユースケースがシンプルで1つのテキストのみを必要とする場合は、文字列が適しています。

<Note>
  Jevはテキストのみを受け付けます。状態は文字列、JSONオブジェクト、またはテキスト値の配列である必要があります。画像、音声、動画はサポートされていません（まだ）。Jevの主要なトレーニング言語は英語です。CJKスクリプトを含む他の言語も受け付けますが、現在は精度が低くなっています。詳細は[Models](/models#language-support)を参照してください。
</Note>

```json title="状態としてのサポート会話" theme={null}
{
  "ticket": {
    "subject": "二重請求",
    "messages": [
      {"from": "customer", "text": "注文A-104で2回請求されました。重複分を返金してください。"},
      {"from": "support", "text": "請求内容を確認しています。"}
    ]
  },
  "order": {
    "id": "A-104",
    "charges": [
      {"amount_usd": 49, "status": "captured"},
      {"amount_usd": 49, "status": "captured"}
    ]
  },
  "refund_policy": "二重請求は返金の対象となります。"
}
```

このオブジェクトは、会話、注文、およびポリシーを含んでいますが、1つの状態です。判断にそれらのパーツの比較が必要な場合は、関連情報をまとめて配置してください。

## コンテンツと質問を分離する {#separate-content-from-questions}

状態にはコンテンツと裏付けとなる事実を含めます。[質問](/primitives)は、そのマテリアルについてモデルが行うべき判断を定義します。たとえば、返金リクエストとポリシーを状態に含め、顧客が返金を要求したかどうか、およびポリシーがそれを支持するかどうかを質問します。

指示、基準、質問タイプ、および1つの状態に対して複数の質問を行う方法については、[プリミティブ（質問）](/primitives)を参照してください。

リクエストスキーマについては[APIリファレンス](/api)を、インストール、型付き入力、およびレスポンス処理については[クライアントSDK](/sdk)を参照してください。
