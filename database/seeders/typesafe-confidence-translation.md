# 確信度 {#confidence}

> TypeSafeが確実性をどのように報告するか、確率との違い、そしてシステムの動作を制御するためにどのように使用するか。

TypeSafeのすべてのScoreおよびChoiceの回答には、オプション（Choiceの場合）またはレベル（Scoreの場合）全体の確率分布を表す`probabilities`プロパティが含まれます。その分布の*形状*がモデルの確実性を示します。一つの結果に集中している場合は確信度の高い回答を意味し、分散している場合は不確実な回答を意味します。

回答の`confidence`プロパティは、その形状を0から1の単一の数値に集約するため、自分で計算することなくしきい値を設定できます。（Noulの回答にはこれは含まれません。）

## 確信度は確率から導出される {#confidence-is-derived-from-the-probabilities}

`confidence`は、回答がすでに提供している確率分布から計算される統計です。TypeSafeはすべてのChoiceおよびScoreの回答に対してこれを計算して返すため、一般的なケースでは追加の作業は不要です。

<Note>
  **確かなデフォルト値：** `confidence`はほとんどのユースケースに適した便利な指標として提供していますが、私たちの定義に縛られることはありません。評価する内容によっては、別の指標の方が適している場合があります。だからこそ、レスポンスに完全な`probabilities`を含めています。さまざまな計算方法の長所と短所は専門的なトピックであり、このページではなく別のクックブックで取り上げます。追加した際にリンクをこちらに掲載します！
</Note>

[Choice](/primitives/choice)の場合、分布はオプション全体の`probabilities`です。[Score](/primitives/score)の場合、レベル全体の分布です。どちらの場合も、分布が平坦であれば確信度が低いことを意味します。Choiceの確信度が低い場合、他のオプションに比べて明確に優れたオプションがないことが多く、Scoreの確信度が低い場合、レベルが曖昧または多次元的であるか、状態に十分な情報が含まれていないことが多いです。

## 「わからない」は有用なシグナルである {#i-dont-know-is-a-useful-signal}

人間であれ機械であれ、インテリジェントなシステムが正直な不確実性を表現できない場合、そのシステムは信頼できません。

確信度は、モデルが「これについては確信が持てない」と言うための組み込みメカニズムを提供します。これにより、コードが確実性のレベルに応じて異なる動作を実装できるようになり、実際に信頼できるシステムを構築するための基盤となります。

## コードで確信度を使用する3つの方法 {#three-paths-for-using-confidence-in-your-code}

有用な出発点となるパターンは、確信度を3つの範囲に分け、それぞれ異なるシステムの動作を生成することです。

**確信度が高い：** 自動的に実行する。モデルが明確に判断しており、人間の関与なしに進めることができます。

**確信度が中程度：** 慎重に進める。モデルは妥当な回答を持っているが、確信はない。コンテキストによっては、ユーザーに確認を求めたり、レビューのためにフラグを立てたり、実行前に追加情報を収集したりする場合があります。

**確信度が低い：** 実行しない。人間にルーティングし、clarificationを求めるか、別のシステムにフォールバックする。モデルは十分な情報がないか、その質問が適していないことを伝えています。

境界をどこに引くかは、リスクの大きさによって異なります。

## しきい値はリスクに応じてスケールする {#thresholds-scale-with-risk}

確信度のしきい値は一つの数値ではありません。同じシステム内の異なるアクションは、誤った場合の結果に応じて異なるレベルでゲートされるべきです。

```python theme={null}
response = client.system_one(
    state=user_message,
    questions={
        "action": Choice(
            instructions="ユーザーは何をしようとしていますか？",
            criteria={
                "check_balance": "口座残高を確認する",
                "approve_transfer": "保留中の出金リクエストを承認する",
                "support": "問題についてサポートを受ける",
            },
        ),
    },
)

action = response.answers["action"]
confidence = action.confidence

if confidence < 0.5:
    # モデルが本当に不確かな場合。推測しない。
    route_to_human(user_message)

elif action.choice == "check_balance":
    # リスクが低い。間違った画面を表示しても回復可能。
    show_balance(account_id)

elif action.choice == "approve_transfer":
    if confidence > 0.9:
        # リスクが高く、確信度も高い。確認して実行する。
        confirm_then_execute(account_id)
    else:
        # リスクが高く、確信度は中程度。先に確認する。
        ask_user_to_confirm(account_id)
```

0.5の確信度フロアは、モデルが本当に不確かだと報告するものをすべて捕捉します。それ以上の場合、破壊的な操作に対して確認なしで実行するためのしきい値は、読み取り専用の操作よりも高くなります。コードがリスク許容度をエンコードします。

<Note>
  正しいしきい値はドメインとユースケースにおけるモデルのパフォーマンスによって異なります。保守的なしきい値から始め、独自のデータでテストし、結果を観察しながら調整してください。
</Note>
